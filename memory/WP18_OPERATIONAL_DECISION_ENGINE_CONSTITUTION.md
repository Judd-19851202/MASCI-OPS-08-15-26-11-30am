# WP-18 Operational Decision Engine Constitution

Date: 2026-08-04

## Constitutional status

**Decision label:** `APPROVED_CONSTITUTIONAL_DECISION`  
**Proof label:** `EXECUTIVE_DIRECTIVE`

This amendment is permanently inherited by all remaining WP-18 work packages and every future work package unless explicitly superseded by Executive Constitutional Amendment.

It complements — not replaces — the:

1. **WP-17 Product Constitution**
2. **WP-18 ECAP**
3. **WP-18 Operational Intelligence Constitution**

## Primary mission

The platform shall evolve into the operating system for heavy civil construction.

Every operational fact shall become trusted intelligence.
Every trusted intelligence item shall improve decisions.
Every decision shall become measurable.
Every measurable outcome shall continuously improve future recommendations.

## The decision pipeline

Every operational fact shall follow one governed lifecycle:

**Capture → Validate → Connect → Understand → Recommend → Approve → Execute → Measure → Learn → Improve**

No subsystem may stop at merely collecting information.

## Every package must add intelligence

Every future package must prove measurable improvements in at least one of these areas:

- operator productivity
- PM productivity
- superintendent productivity
- executive visibility
- forecasting accuracy
- production understanding
- schedule confidence
- budget confidence
- resource utilization
- automation
- duplicate-entry reduction
- explanation quality

If a package cannot demonstrate measurable value, it cannot receive a **GO**.

## Governed metric engine

Every operational metric shall have:

- one owner
- one calculation
- one definition
- one validation path
- one audit trail
- unlimited consumers

The platform shall never calculate these in multiple places as competing truths:

- production
- productivity
- utilization
- variance
- cost / unit
- schedule health
- ROI
- forecast
- earned value

Everything shall consume one governed metric engine.

## The Work Block becomes the digital heart

The Work Block becomes the primary operational object.

Everything connects to it.

Each Work Block should eventually understand:

- project
- phase
- work package
- schedule activity
- customer pay item
- internal work type
- internal cost code
- budget line
- baseline schedule
- current schedule
- forecast schedule
- crew
- employees
- labor
- equipment
- materials
- vendor / subcontractor
- production
- constraints
- QA/QC
- safety
- photos
- weather
- tickets
- AI observations
- executive KPIs

Everything references the Work Block.
Nothing duplicates it.

## Digital twin maturity

Each project should mature through these levels:

1. **Level 1** — Connected records
2. **Level 2** — Connected operational workflows
3. **Level 3** — Automatically derived relationships
4. **Level 4** — Operational intelligence
5. **Level 5** — Predictive recommendations
6. **Level 6** — Executive explanation engine

WP-18 should intentionally move the platform through these maturity levels.

## Resource knowledge engine

The platform continuously learns — not guesses.

For every:

- employee
- crew
- foreman
- superintendent
- PM
- equipment unit
- vendor
- subcontractor
- material
- work package
- schedule activity

the system should improve its understanding over time using governed evidence.

No permanent conclusions without human authority.

## Operational explanation engine

Every KPI should eventually answer:

- Why?
- Compared to what?
- Since when?
- What’s driving it?
- What’s at risk?
- What’s improving?
- What’s getting worse?
- What evidence supports this?
- What action is recommended?
- How confident is that recommendation?

Dashboards should explain, not simply display.

## Continuous improvement engine

Every completed project should automatically improve future projects.

Examples:

- better production expectations
- better crew recommendations
- better schedule templates
- better duration estimates
- better material planning
- better equipment planning
- better staffing guidance
- better subcontractor recommendations
- better risk identification

Institutional knowledge should accumulate, not disappear when people leave.

## Zero extra administration

Every enhancement must reduce administrative effort.

Operators should spend more time building and less time typing.

Whenever possible, the platform should:

- derive
- infer (with confidence and review)
- suggest
- automate
- reuse

instead of asking for another field.

## Executive readiness

When C10 is complete, the platform should be able to answer questions like:

- Which projects are genuinely healthy?
- Which ones only appear healthy?
- Which crews consistently outperform?
- Where are we losing margin?
- Which constraints recur?
- Which PM practices lead to success?
- Which equipment is underutilized?
- Which subcontractors create risk?
- What should we do next Monday morning?

Those answers should be evidence-backed, explainable, and traceable.

## Permanent certification gate

No future package may receive **GO** unless it proves:

- preserves constitutional trust lines
- strengthens operational intelligence
- reduces duplicate work
- improves downstream value
- keeps a single source of truth
- preserves operator simplicity
- strengthens executive decision quality
- remains WP-17 compliant
- remains ECAP compliant
- remains Operational Intelligence Constitution compliant
- remains Operational Decision Engine compliant

## Executive recommendation after C5

After C5, the platform should **not** jump straight into merely “building production.”

C6 should be the package where the platform learns to **understand production**.

That means:

- deriving production metrics from the Work Block
- establishing the single governed metric engine
- introducing crew, equipment, material, and subcontractor intelligence
- ensuring every downstream KPI consumes those governed calculations

## Final constitutional directive

The platform is not merely collecting records.

It is building a governed operational decision engine for a heavy civil contractor.

Every fact must improve understanding.
Every understanding must improve decisions.
Every decision must become measurable.
Every measurable result must improve the next recommendation.
