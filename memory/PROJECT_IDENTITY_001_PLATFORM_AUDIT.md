## 0. EXECUTIVE SUMMARY

### 0.1 Verdict

> **The MASCI Operations Platform has a confirmed platform-wide defect: project identity is derived from submitter-entered free-text instead of from `jobs_master`. The defect is verified live in 2 production modules (Daily Reports, Job Photos) and present, in varying severity, in 9 other modules. `jobs_master` is sufficient to act as the canonical source of project identity, but it is currently consulted by only one consumer of `JobFolderList` (Daily Reports). All other modules display whatever the submitter typed.**

### 0.2 Production Evidence (verbatim from `masci_safety` DB on audit run)

| PN (canonical) | Canonical Name (jobs_master)                             | Free-text variants observed                                              | DR rows | Photo rows |
|----------------|----------------------------------------------------------|--------------------------------------------------------------------------|--------:|-----------:|
| `26-01 - CP`   | `NSB Corbin Park Stormwater Improvements`                | `Corbin park`, `NSB Corbin Park Stormwater Improvements`                 |      12 |         74 |
| `24-12`        | `CC5744 - OXFORD RD Improvements (OXFORD)`               | `Oxford coping`, `CC5744 - OXFORD RD Improvements (OXFORD)`              |      52 |        351 |
| `25-21`        | `SJR2C - Loop Trail - Spruce Creek`                      | `Loop trail `, `SJR2C - Loop Trail - Spruce Creek`                       |      25 |        193 |
| `26-07`        | `University High Parent Loop Ext`                        | `University high school`, `University High Parent Loop Ext`              |       3 |         30 |

> These four PNs match the four duplicate folders the user reported in **both Daily Reports and Job Photos** screens. The user’s report is fully reproduced from raw production data.

### 0.3 The Defect Class

The duplicate-folder behaviour is generated by **one specific grouping pattern** in the UI:

```js
const key = `${project_number}::${project_name}`;
```

Any two records that share the same `project_number` but have a different (or whitespace-different) `project_name` are bucketed into separate folders. Because submitters can free-type the name field (and historically did), every job that has been entered with two different names will appear as two folders, two counts, two contact strips, and two entries in any per-project rollup.

`JobFolderList.jsx` has already been fixed to key on **project_number only** (DR-JOB-002). But the canonical name map (`jobsMaster` prop) is consumed by only **one** of its seven callers — Daily Reports.

`JobPhotosLibrary.jsx` is **not** using `JobFolderList`; it has its **own grouping loop** which still uses the `${number}::${name}` key. **Confirmed broken.**

## 7. SHARED RESOLVER DESIGN (DESIGN ONLY — NOT BUILT)

### 7.1 API

```
resolveProjectIdentity(record, ctx={ jobsMasterById, jobsMasterByPn, aliasMap })
  → {
      canonical_project_number,
      canonical_project_name,
      jobs_master_id,
      submitted_project_number,
      submitted_project_name,
      resolution_status,   // see §7.3
      confidence,          // 0–100
      source,              // "jobs_master_id" | "jobs_master_pn" | "alias" | "submitted" | "orphan" | "cert"
    }
```

### 7.2 Resolution Order (deterministic, top-first)

1. **`canonical`** — `record.jobs_master_id` present **and** found in jobs_master → return canonical name+number from that row. Confidence = 100.
2. **`project_number_match`** — `record.project_number` (or `job_number`) exact-matches `jobs_master.project_number` (case-insensitive after `trim()`) → return canonical name+number. Confidence = 95.
3. **`project_number_normalized`** — Apply normalization (collapse spaces around `-`, strip suffixes like `-CP`) and re-attempt match. If exactly one jobs_master row matches → return canonical. Confidence = 85.
4. **`alias_match`** — `record.project_number` is in `aliasMap` (admin-curated map, persisted in `jobs_master_aliases` collection — to be built in PROJECT-IDENTITY-005). Confidence = 90.
5. **`cert_hidden`** — `record.project_number` or `record.project_name` matches the cert/test regex (§5). Return `submitted_*` values + `resolution_status="cert_hidden"`. Confidence = 100.
6. **`submitted_only`** — `record.project_number` present but no canonical match. Return `submitted_*` values + flag for admin reconciliation. Confidence = 30.
7. **`orphan`** — `record.project_number` blank. Return name-only or fully blank with `resolution_status="orphan"`. Confidence = 0.

### 7.3 `resolution_status` values

`canonical` · `project_number_match` · `project_number_normalized` · `alias_match` · `submitted_only` · `orphan` · `cert_hidden`

### 7.4 Caller Contracts
