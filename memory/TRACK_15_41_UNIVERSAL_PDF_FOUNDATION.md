# TRACK 15.41 · Universal PDF Foundation — Architecture

**Date:** 2026-06-19
**Status:** 🟢 LIVE · v15.41.1
**Adopted by:** 6 of 30 PDF surfaces (the Top-6 operational PDFs)

---

## 1 · Why a foundation (operator brief)

Across the platform, ~30 generators were each redoing their own header,
footer, branding, and metadata. The result:
* MASCI hard-coded into every PDF
* Inconsistent header/footer chrome
* No way to swap branding for a future ForgedOps customer without
  editing 30 files
* No legal-discovery audit trail beyond per-PDF ad-hoc footers

The foundation provides **one set of helpers** that any PDF can adopt
**additively** — meaning the existing PDF body is untouched and the
foundation chrome layers on top.

### 2.1 · Public API (TRACK 15.41 additions)

| Symbol | Purpose |
|---|---|
| `WhiteLabelConfig` (dataclass) | Frozen brand config — name, long name, logo URL, color, footer tagline, legal line, platform owner. |
| `get_white_label()` | Read `PDF_BRAND_*` env vars with MASCI fallbacks. Called fresh per render so an env change takes effect on the next PDF without a backend restart. |
| `build_audit_block_html(record_id, source_module, project=None, document_version=None, generated_by=None, generated_at=None)` | HTML snippet — last-page friendly audit block. Renders Record ID · Source Module · Project · Document Version · Generated By · Generated On · Environment · Foundation. Page-break-avoidant. |
| `build_metadata_block_html(document_type, document_id=None, project_number=None, extra=None)` | HTML snippet — small monospace meta strip suitable for placement near the document header. |
| `PDF_FOUNDATION_VERSION = "15.41.1"` | Version stamp embedded in every audit block. Bump on each future track that revises the foundation. |

### 2.2 · Pre-existing API (unchanged)

| Symbol | Purpose |
|---|---|

## 3 · White-label env vars

| Var | Default | Purpose |
|---|---|---|
| `PDF_BRAND_NAME`         | `MASCI` | Short brand name (for the brand mark) |
| `PDF_BRAND_LONG_NAME`    | `MASCI Operations Platform` | Long brand name (for the header kicker) |
| `PDF_BRAND_LOGO_URL`     | `""` | Optional remote/data-URI logo override (current PDFs use baked-in `masci-mark-onlight.png`) |
| `PDF_BRAND_COLOR_HEX`    | `c8102e` | Accent color (without `#`) |
| `PDF_BRAND_FOOTER_TAGLINE` | `Generated through MASCI Operations Platform — Powered by ForgedOps™ \| © 2026 ForgedOps™` | @bottom-left footer text |
| `PDF_BRAND_LEGAL_LINE`   | `MASCI General Contractors Inc. · 386-322-4500 · mascidocs.com` | Legal-line footer |

**NEVER overridden:** `platform_owner = "ForgedOps™"`. The foundation is
ForgedOps-branded; customer-facing branding is fully overridable.

## 4 · Environment tag

`_env_tag()` derives the environment label from `DB_NAME`:

| `DB_NAME` substring | Tag |
|---|---|
| contains `preview` | `PREVIEW` |
| contains `stag`    | `STAGING` |
| contains `dev`     | `DEV` |
| anything else      | `PRODUCTION` |
| missing            | `UNKNOWN` |

Tag appears in every audit block so legal discovery can immediately
distinguish a preview-environment PDF from a production PDF.

## 5 · Adoption pattern (additive, zero data loss)

### 5.1 · WeasyPrint HTML PDFs (the Top-6 path)

```python
# Top of file
from pdf_branding import build_audit_block_html, build_metadata_block_html

# In the renderer, just before the closing </body>:
{build_metadata_block_html(
    document_type="Safety Meeting",
    document_id=canonical_ref,
    project_number=record.get("project_number"),
)}
{body}  # existing body content — UNCHANGED
{build_audit_block_html(
    record_id=canonical_ref or record.get("id"),
    source_module="safety.meeting",
    project=record.get("project_name"),
    generated_by=record.get("conducted_by") or "system",
)}
```

## 6 · Hard rules respected

* No new collections.
* No new endpoints.
* No schema changes.
* No body content rewrites.
* No new authentication paths.
* No new authorization paths.
* Existing CSS (`BRAND_CSS`) untouched.
* Existing helpers (`brand_header`, `wrap_pdf_html`) untouched.
* All 22 not-yet-adopted PDFs continue to render identically.

---

## 7 · Foundation version policy

* Bump `PDF_FOUNDATION_VERSION` whenever the audit block layout or
  semantics change. The version is embedded in every audit block.
* Foundation **DOES NOT** change PDF body content; bumping the
  foundation version never invalidates an old PDF.
