# Track 19.02C · Cleanup Plan (executed)

Every action below is **constrained to paths classified SAFE TO DELETE**
in `TRACK_19_02C_CLEANUP_CLASSIFICATION.md`. No production data,
customer uploads, active media, backups, audit logs, or rollback assets
are touched.

## Protected paths (REJECTED from any delete command)

* `/app/backend/storage/**` — customer uploads
* `/app/backend/static/**` — production media + assets
* `/app/backend/backups/**` — local backup snapshots
* `/app/backend/.env`, `/app/frontend/.env`
* `/app/backend/server.py` and all backend source
* `/app/frontend/src/**`, `/app/frontend/public/**`
* `/app/frontend/node_modules/**` EXCEPT `/app/frontend/node_modules/.cache`
* `/app/.git/**` — platform git store
* `/app/memory/*.md` and `/app/memory/track_*/`
* All database / R2 references (off-filesystem)

## Hard rules enforced

* **No `rm -rf` against any path not in the SAFE-TO-DELETE list.**
* **No production data deletion.** No path under `storage/`, `static/`, `backups/`.
* **No customer upload deletion.** `project_docs/` is fully protected.
* **No database deletion.** MongoDB is not on this filesystem; nothing referencing the DB is touched.
* **No blind wildcards.** Each command targets a leaf path or uses explicit `-name` filters.

## Skipped actions (out of scope for this track)

* Compressing /var/log MongoDB logs — not on /app filesystem.
* Cleaning /root/.cache (yarn / npm / pip) — not on /app filesystem.
* Running `git gc --aggressive` on /app/.git — saves marginal space and risks repacking the platform's commit chain. Left for future hygiene.
* Reducing the local backup retention window — current `BACKUP_KEEP_MAX=3` already limits to ~6–8 MB, not a contributor.
* Pruning customer PDFs in `project_docs/24-12/` — PRODUCTION DATA, protected.

## Order of execution

Actions 1 → 2 → 3 → 4 → 5 → 6 in order. After each action, the
reclaim is verified via `df -h /app`.
