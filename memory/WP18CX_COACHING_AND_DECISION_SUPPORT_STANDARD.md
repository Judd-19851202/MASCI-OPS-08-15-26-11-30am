# WP18CX Coaching and Decision Support Standard

## Standard
Coaching is allowed only when it improves an operator decision.

## Required coaching pattern
Every meaningful coaching block should answer:
1. What changed?
2. Why does it matter?
3. What should happen next?
4. Who owns it?
5. What happens if nothing is done?

## Approved coaching style
- brief
- operational
- evidence-aware
- role-appropriate
- removable when no action is needed

## Rejected coaching style
- tutorial narration
- architecture exposition
- AI self-reference
- repeated warnings with no action

## Certified implementations in WP18CX
- `Project Performance` recommendation cards now expose owner, source, evidence, confidence, and drill-down path in operator-safe wording.
- `Project Schedule`, `Project Budget`, and `Project Controls` primary headings now explain the workflow in job-language rather than system-language.
- override actions were rewritten from technical override phrasing to `Record different decision` / `Save decision` language.

## Gaps remaining
- PDF/email narrative coaching is not fully runtime-certified.
- AI-summary channel wording still requires direct runtime evidence for full constitutional signoff.
