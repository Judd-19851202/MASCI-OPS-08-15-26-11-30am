# WP18 ECAP Role-Based Operating Experience

Date: 2026-08-03

## Final operator experience law

**Decision label:** `APPROVED_CONSTITUTIONAL_DECISION`  
**Proof label:** `DOCUMENTED_ONLY`

WP-18C may add architectural clarity, but it may not increase operator complexity merely to satisfy an internal architecture preference.

This is now reinforced by the standing Operational Intelligence Constitution: every future package must reduce operator burden where applicable and create downstream reuse or decision value.

## Experience rules by role family

| Role family | Final rule |
|---|---|
| Executive | sees one governed hierarchy with drill-down and exception confidence |
| Operations | sees one cross-project view of constraints, resource pressure, and readiness |
| PM / project engineer | keeps existing PM shell and gains governed budget / forecast / EV clarity |
| Superintendent / foreman | keeps current field workflows and gains better review feedback, not more hidden burden |
| Dispatch / transportation | keeps current dispatch shell and gains cleaner upstream demand / readiness context |
| Safety / QA/QC | keeps current workflows and gains explicit downstream consequence linkage |
| Shop / mechanic | keeps current workflows and gains clearer readiness / cost impact context |
| HR / training | keeps current workflows and gains better qualification / labor trust lines |
| Accounting / finance | receives the largest substantive architectural addition because finance authority is currently underbuilt |

## Entry / completion / return-path law

Every workflow introduced in WP-18C must define:

1. entry point
2. required action
3. approval or completion state
4. return path to the prior operator context

No stranded screen or dead-end workflow is allowed.

No workflow is constitutionally complete if it collects information without creating downstream operational or executive value.

## Operator language law

No internal engineering language may appear in operator UI.  
Backend terms may remain canonical in English, but operator-facing labels must stay operational and human-readable.
