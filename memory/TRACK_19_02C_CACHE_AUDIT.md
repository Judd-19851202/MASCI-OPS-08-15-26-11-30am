## Webpack cache safety verification

* **Not required at runtime.** The `.cache/default-development/`
  directory is webpack-loader cache (`babel-loader`, `webpack`'s
  built-in cache). On next `yarn start` (CRA), webpack recreates the
  cache automatically.
* **First compile after delete** will be slightly slower (~30s vs ~10s)
  — but the running CRA dev server in this environment already kept its
  state in memory; the disk cache is purely a warm-start accelerator.
* **No restart triggered** by this track. The frontend continues to
  serve from the in-memory CRA dev server uninterrupted.
