## 4 · Excluded-content rules (NOT operational fields)

The comparator skips the following moving-target lines, since they
intentionally change per render and do not represent operational
content loss:

* `Page X of Y` pagination artifacts.
* `Generated <human-date>` per-render timestamps (any case).
* ISO timestamps (`2026-06-19T14:35:00Z`).
* `sha256=...` 16-char audit fragments.
* Foundation chrome rows: `DOCTYPE: ...`, `DOCID: ...`, `PROJECT#: ...`,
  `GENERATED: ...`, `GENERATED ON ...`, `GENERATED BY ...`, `RECORD ID ...`,
  `SOURCE MODULE ...`, `DOCUMENT VERSION ...`, `ENV ...`,
  `ENVIRONMENT ...`, `FOUNDATION V ...`, `AUDIT TRAIL ...`, `EXPORTED: ...`.

Operational data (names, IDs, signatures, narratives, equipment rows,
photos, attendees, action items, notes, attachments) is **not** in
the exclusion list and **must** appear in the AFTER text.

## 5 · Why this is bulletproof

* The fingerprint set is built from stripped, non-empty lines —
  whitespace and pagination noise are not significant.
* pdfminer.six is used as the extractor — it is deterministic for a
  given PDF byte stream.
* The comparator is line-level set equality: an entire line either
  appears in AFTER or it doesn't. Subtle drift (case, punctuation)
  would be flagged.
* The 16-PDF coverage spans both engines (WeasyPrint + ReportLab),
  three call patterns (`wrap_pdf_html` kwargs · inline HTML inject ·
  ReportLab Flowable append), and 9 source modules.
