# WP16 Platform Visual Constitution

## Visual language
The MASCI operating system should feel like software commissioned by a Fortune 100 heavy civil contractor for field operations.

## Canonical visual traits
- Hard borders and structural hierarchy over decorative shadows.
- Industrial typography with strong display weight and technical body text.
- Light, glare-resistant surfaces with dark ink and one rugged accent color.
- Deliberate spacing and left-aligned reading flow.
- Motion that confirms action, not motion that entertains.

## Iconography standard
- One curated icon family only.
- Icons must communicate utility, equipment, operations, review, or status clearly.
- Decorative icon swaps are forbidden.
- Critical state icons must always pair with text.

## Copy and tone standard
- Calm, concise, directive.
- Confident without sounding robotic.
- Industrial and professional, never trendy.
- Operator-first language, not implementation-first language.

## Component visual rules
- Shared shell, page header, cards, forms, tables, and states must use the same border rhythm.
- Accent color is reserved for attention, command, and primary action.
- Success, warning, and critical states must remain semantic and consistent.
- Empty and loading states must still feel like part of the same operating system.

## Quality bar
If a screen feels like a stock dashboard, template leftover, or mismatched application, it violates WP-16.
