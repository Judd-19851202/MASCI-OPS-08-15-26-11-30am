# WP-17B Implementation Roadmap

## Rule
This file authorizes sequence only. It does **not** start WP-17C.

## Recommended WP-17C execution order
1. **Portal entry + IA canon**
   - sign-in / launch-point rebuild
   - companion-lane governance
   - Admin top-level taxonomy lock
2. **Navigation and shell standardization**
   - one nav family per portal
   - Transportation dual-shell resolution
   - cross-portal sidebar behavior parity
3. **Dashboard and hub canonicalization**
   - Admin, Shop, Executive first
   - PM / HR / Safety / Dispatch harmonization second
4. **Form / table / overlay standardization**
   - validation language
   - action placement
   - density ladder
5. **Workflow simplification**
   - remove alias-route confusion
   - clarify create/submit/review progression
6. **Terminology / coaching / icon / white-label pass**
7. **Hidden-route cleanup and final responsive certification**

## Highest-risk dependencies
- `WP-17C`: information architecture, launch points, navigation canon
- `WP-17D`: component/system standardization
- `WP-17E`: workflow simplification and form/table behavior
- `WP-17F`: terminology, content, coaching, labels
- `WP-17G`: white-label parity
- `WP-17H`: responsive, regression, hidden-route governance, final closeout

## Executive recommendation
- Begin WP-17C with Admin + entry architecture, not with portal-wide cosmetic changes.
- Preserve all current business logic owners while changing only hierarchy, navigation, shell consistency, and canonical labeling.
