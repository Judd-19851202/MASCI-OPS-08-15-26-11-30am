# WP-17C Canonical Page Anatomy

## Dashboard page
1. Mission/context strip
2. Attention summary / posture strip
3. Next actions / priority queues
4. High-value KPIs only
5. Core work queue or domain cards
6. Supporting information / recent changes
7. Coaching/help where it increases action clarity

## List page
1. Title + purpose
2. Search / filters / quick actions
3. Results summary
4. List/table/cards
5. Empty/loading/error state
6. Contextual detail entry
7. Bulk actions only when truly needed

## Detail page
1. Identity/context hero
2. Status + primary actions
3. Summary blocks
4. Tabs or sections by concept, not raw data source
5. Audit/history / related records
6. Back navigation

## Form page
1. Purpose and scope
2. Progress/context
3. Logical section grouping
4. Canonical controls and validation patterns
5. Save/autosave/submit state
6. Cancel/back behavior
7. Completion confirmation / next step

## Operational queue page
1. Priority order
2. Ownership
3. Due date / SLA context
4. Status
5. Next action
6. Filters / escalation context

## Configuration page
1. Audience and risk statement
2. Grouped settings
3. Save/revert behavior
4. Auditability
5. No hidden side effects

## Table-heavy page
1. Purpose + refresh context
2. Summary strip
3. Tabs/views only when they reduce noise
4. Sticky header and readable first column behavior
5. Mobile fallback strategy

## Modal / drawer workflow
1. Context title
2. Why the drawer/modal exists
3. Primary action
4. Secondary exit path
5. Error/loading/empty behavior
6. No hidden destructive action without clear affordance
